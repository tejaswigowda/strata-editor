Make a Pythagorean-theorem short

A 59-second proof that 3² + 4² = 5²: fifty tiles, one triangle, three labels and a camera that turns round to an end card. It is built entirely by hand, no AI, with the JS Shell and the Universal Timeline. Open the editor, open the Shell tab, and paste each block in order — or open the finished scene, pyth.json (step 11).

Why the Shell, not clicking. Every edit below is a real, undoable, git-diffable command (editor.execute(...) under the hood) — the Shell is just the fastest way to author them. You can always inspect or hand-tweak the result afterward in the Outliner/Object panel; nothing here is a special "script mode."
One paste, one scope. The Shell does not keep variables between pastes, so every block below is self-contained: it defines what it uses, and anything a later block needs is found again by name or class ($S('#three'), $S('.cube')). Start from an empty scene.

1 Build the three squares out of tiles

The proof needs the squares to come apart and go back together, so each one is made of unit tiles instead of one big box. A tile is a 1×1×0.1 slab. Tiles sit in a row or a column group, and the group sits in a square group: #3x3-square › #3col1 › cube_3.1.1. That nesting is what lets the timeline say "the first column of the 3×3" later.

// A square of side n is n lines (rows or columns) of n tiles. Each tile is a
// 1 x 1 x 0.1 slab; each line is its own group so the timeline can address it.
function makeSquare(n, name, color, kind, place) {
  const square = new Group();
  square.name = name;
  for (let k = 1; k <= n; k++) {
    const line = new Group();
    line.name = `${n}${kind}${k}`;
    for (let m = 1; m <= n; m++) {
      const tile = new Mesh(
        new BoxGeometry(1, 1, 0.1),
        new MeshStandardMaterial({ color, roughness: 0.6, metalness: 0.2 })
      );
      tile.name = `cube_${n}.${k}.${m}`;
      tile.position.set(...place(k, m), 0);
      tile.castShadow = tile.receiveShadow = true;
      tile.userData.hasEdgeOutline = true; // black border, drawn by the viewport
      line.add(tile);
    }
    square.add(line);
  }
  editor.execute(new AddObjectCommand(editor, square));
  return square;
}

// 3x3 on the vertical leg: columns, column 1 touches the triangle.
makeSquare(3, '3x3-square', 0xff6b6b, 'col', (k, m) => [1 - k, 3 - m]);
// 4x4 under the horizontal leg: rows, row 1 touches the triangle.
makeSquare(4, '4x4-square', 0x4ecdc4, 'row', (k, m) => [m, -k]);
// 5x5 on the hypotenuse: built upright, then turned onto the slope.
const big = makeSquare(5, '5x5-square', 0x333300, 'row', (k, m) => [m - 0.5, 5.5 - k]);
big.position.set(4.5, -0.5, 0);
big.rotation.z = Math.atan2(4, 3);   // 53.13 degrees, the angle of the 3-4-5 triangle

Give everything an addressable class — squares, lines and tiles — so selectors like #3x3-square #3col1 .cube and .cube work. Class names are stored lowercase, so use lowercase everywhere:

$S('#3x3-square, #4x4-square, #5x5-square').addClass('square');
$S('#3x3-square > *').addClass('col');
$S('#4x4-square > *, #5x5-square > *').addClass('row');
$S('#3x3-square > * > *, #4x4-square > * > *, #5x5-square > * > *').addClass('cube');
$S('.cube').nodes.filter(n => n.name.startsWith('cube_')).length   // 50 tiles: 9 + 16 + 25
Selectors reach down. A class on a node also matches everything inside it, and each tile's black border is a child of the tile, so $S('.cube').nodes.length says 100, not 50: the 50 tiles and their 50 borders. That is harmless — the borders follow their tiles through every fade and flight, and moveToEach pairs borders with borders in the same order — but it is why the check above filters by name.
Why the 5×5 is built upright and then turned. Its tiles end up lying on the hypotenuse, so the whole group is rotated by the triangle's angle. Because the rotation lives on the group, every tile inherits it — and when the other 25 tiles later fly onto these cells, they turn to match. You never type a rotation for an individual tile.

2 Add the right triangle

Legs 4 and 3, one unit thick, with its right angle on the corner the 3×3 and the 4×4 share. The 5×5 sits on the long side.

const tri = new Mesh(
  new ExtrudeGeometry(
    new Shape([new Vector2(0, 0), new Vector2(4, 0), new Vector2(0, 3)]),   // legs 4 and 3
    { depth: 1, bevelEnabled: false }
  ),
  new MeshStandardMaterial({ color: 0xd99b30, roughness: 0.9, metalness: 1 })
);
tri.geometry.translate(0, 0, -0.5);        // centre the 1-unit thickness on z = 0
tri.name = 'RightTriangle';
tri.position.set(0.5, -0.5, 0);            // right angle sits at the corner the squares share
tri.castShadow = tri.receiveShadow = true;
tri.userData.hasEdgeOutline = true;
editor.execute(new AddObjectCommand(editor, tri));

3 Three text labels

Text isn't scriptable from the Shell directly (font loading needs the UI's loader) — use the Text stencil three times, then rename each one. This is the one click-driven step before the camera.

  1. Open Stencils → Mesh → Text and click it three times. You get three objects, each reading "THREE.JS".
  2. Select the first. In the Object panel set Name to three. Select the second and name it four, the third eqn.

You never set their text in the panel. Every word they show comes from .change() events on the timeline, so the placeholder "THREE.JS" is overwritten at 0 s. Position them and give them a class like anything else:

$S('#three').moveTo(-1, 3.1, 1.24);     // beside the top of the vertical leg
$S('#four').moveTo(2.5, -4.8, 1.24);    // under the 4x4
$S('#eqn').moveTo(-1.3, -2.4, 1.24);    // where the sum will be assembled
$S('#three, #four, #eqn').addClass('label');

4 Background and a glow for the text

makeTexture is a Shell helper — hand it a function that paints a 2D canvas, and it returns a ready-to-use texture. The default environment lights the scene from the background, so ask for it to be rebuilt once the background changes, otherwise the tiles keep the old, brighter lighting. Text lit only by scene lights goes faint on a dark ground, so give the labels some light of their own:

scene.background = makeTexture((ctx, size) => {
  const g = ctx.createLinearGradient(0, 0, 0, size);
  g.addColorStop(0, '#1b2340');
  g.addColorStop(0.55, '#141a2e');
  g.addColorStop(1, '#0a0d18');
  ctx.fillStyle = g;
  ctx.fillRect(0, 0, size, size);
}, 512);
setEnvironment('Default');   // rebuild the image-based lighting from the new background

// text lit only by scene lights goes faint on a dark ground: give it a glow of its own
$S('.label').nodes.forEach(o => {
  o.material.emissive = new Color(0xffffff);
  o.material.emissiveIntensity = 0.7;
  o.material.needsUpdate = true;
});

5 The camera and the end card

The film is shot by a camera that lives in the scene, so it can be animated and chosen as a render shot. It looks straight down −Z at the middle of the figure. Behind it, 15 units away, sits the end card — the camera will simply turn round to it.

const cam = new THREE.PerspectiveCamera(50, 16 / 9, 0.1, 2000);
cam.name = 'PerspectiveCamera';
cam.position.set(3, 0.68, 20);              // dead-centre on the figure, looking down -Z
editor.execute(new AddObjectCommand(editor, cam));

Open Stencils → Mesh → Call card and click it. It inserts an addressable plane that embeds the current /about/callcard live and fits it to the viewport camera. Move it behind the real camera instead, make it landscape, and hide it until the reveal:

const card = $S('#callcard').nodes[0];
card.userData.width = 3.2;                  // landscape: the stencil's portrait 1.8 x 3.2 swapped
card.userData.height = 1.8;
card.geometry = new PlaneGeometry(3.2, 1.8);
$S('#callcard').moveTo(3, 0.68, 35).scaleTo(8);   // 15 units behind the camera, 8x bigger
card.rotation.set(0, Math.PI, 0);                  // front face toward the camera's start position
card.material.opacity = 0;
Three details in that block. scaleTo sets an absolute scale; scale would multiply the size the stencil already gave it. A mesh's front is its local +Z, so turning the card half a turn about Y points that front at the camera's start position; if you get it backwards the card shows mirrored (it is double-sided, so it never disappears). And the card is hidden by being fully transparent, not by visible = false, because the reveal only animates opacity. The viewport may show the card stretched until it is re-baked: the Render tab does that, and so does reopening the saved scene.

6 Choreograph the entrances: 3, then 4

Everything from here on is one clock. .at(t) places an event at an absolute time in seconds; durations in .animate() are milliseconds and in .fadeIn() seconds. The beat is the same for both legs: a label counts the length, a one-tile-thin sliver shows up on the leg, and later the sliver unfolds into the whole square.

// the triangle, then the two entrance slivers
$S('#RightTriangle').at(0).fadeIn(1.5);

// 3: the label, the leg-thin sliver of the 3x3, then the whole square
$S('#three').at(0).change('');
$S('#three').at(6).change('3', { transition: 'fade', dur: 400 });
$S('#3x3-square #3col1 .cube').at(6).animate({ to: { positionX: 0.4, scaleX: 0.2, scaleY: 0.9 } }, 100);
$S('#3x3-square #3col1 .cube').at(6).fadeIn(0.8);
$S('#three').at(13).animate({ to: { positionX: -1, positionY: 3.1 } }, 800);
$S('#3x3-square #3col1 .cube').at(14).animate({ to: { positionX: 0, scaleX: 1, scaleY: 1 } }, 400);
$S('#3x3-square #3col2 .cube, #3x3-square #3col3 .cube').at(14).fadeIn(1);
$S('#three').at(16).change('3\u00B2', { transition: 'fade', dur: 400 });

// 4: the same beat, on rows
$S('#four').at(0).change('');
$S('#four').at(9).change('4', { transition: 'fade', dur: 400 });
$S('#4x4-square #4row1 .cube').at(9).animate({ to: { positionY: -0.6, scaleY: 0.2, scaleX: 0.9 } }, 100);
$S('#4x4-square #4row1 .cube').at(9).fadeIn(0.8);
$S('#four').at(23).animate({ to: { positionX: 2.5, positionY: -4.8 } }, 800);
$S('#4x4-square #4row1 .cube').at(24).animate({ to: { positionY: -1, scaleY: 1, scaleX: 1 } }, 400);
$S('#4x4-square #4row2 .cube, #4x4-square #4row3 .cube, #4x4-square #4row4 .cube').at(24).fadeIn(1);
$S('#four').at(26).change('4\u00B2', { transition: 'fade', dur: 400 });
Why a sliver first. The 3 and the 4 are lengths before they are areas. The first column is squashed to 0.2 of a tile wide and moved 0.4 along so it hugs the leg like a ruler (positionX: 0.4, scaleX: 0.2); at 14 s it relaxes to positionX: 0, scaleX: 1 and the other two columns fade in beside it. The animated values are absolute (to:), which is why the "relax" event can name the resting values directly. .change('') at 0 s blanks a label until its first word.

7 The proof: 9 tiles and 16 tiles onto 25 cells

The 5×5 is only a landing pad. Make it invisible from the first frame, then send every tile of the other two squares onto one of its cells. moveToEach pairs sources to targets by order: the sources are listed 3×3 first, so the nine red tiles take the first nine cells (row 1 and the first four of row 2) and the sixteen teal tiles take the rest.

// the 5x5 is only a landing pad: start it transparent so it is never seen, not even at 0 s
$S('#5x5-square .cube').nodes.forEach(t => { t.material.transparent = true; t.material.opacity = 0; });
$S('#5x5-square, #5x5-square *, #5x5-square .cube').at(0).fadeOut(1);

// the proof: 9 tiles + 16 tiles flow onto the 25 pad cells, 3 seconds, in selector-list order
$S('#3x3-square .cube, #4x4-square .cube').at(40).moveToEach('#5x5-square .cube', 3000);
Why 3 seconds, and why a pad. Twenty-five tiles at once blur under about a second; three seconds lets a viewer follow "those nine went there, those sixteen went there". Because the destinations are the pad's actual cell positions and rotations, resolved when the timeline is compiled, the reveal is deterministic and reversible when you scrub, and it re-targets itself if you move the pad. The pad is hidden by starting transparent — a bare fadeOut at 0 s would show it for the first second.

8 The sum, read off the screen

While the tiles are still settling, the labels slide to the bottom into the shape of the sum: 3² + 4², which turns into 9 + 16, closes up into 25, and is then restated as 5² and as the theorem itself. All of it is .change() on the three labels.

// 44-56 s: the sum, read off the screen
$S('#eqn').at(0).change('');
$S('#three').at(44).animate({ to: { positionX: -2.4, positionY: -2.4 } }, 800);
$S('#four').at(44).animate({ to: { positionX: -0.2, positionY: -2.4 } }, 800);
$S('#eqn').at(44).change('+', { transition: 'fade', dur: 400 });

$S('#three').at(47).change('9', { transition: 'fade', dur: 400 });
$S('#four').at(47).change('16', { transition: 'fade', dur: 400 });

$S('#three').at(50).animate({ to: { positionX: -1.3, positionY: -2.4 } }, 1000);
$S('#four').at(50).animate({ to: { positionX: -1.3, positionY: -2.4 } }, 1000);
$S('#three').at(51).fadeOut(0.3);
$S('#four').at(51).fadeOut(0.3);
$S('#eqn').at(51).change('25', { transition: 'fade', dur: 400 });
$S('#eqn').at(53).change('5\u00B2', { transition: 'fade', dur: 400 });
$S('#eqn').at(56).change('a\u00B2 + b\u00B2 = c\u00B2', { transition: 'fade', dur: 400 });
A label per track. The two merging labels are faded out with one $S call each (not $S('#three, #four')), so each label keeps its own timeline track and the code panel reads label by label. Content is a step function: the text is whatever was keyed last; transition: 'fade' only cross-fades the swap (see the animation guide).

9 Turn round to the end card

Last, the camera does not travel anywhere: it turns 180° about Y on the spot while the card behind it fades in. The card was placed 15 units away at 8× scale, and at a 50° field of view that fills the frame.

// 56.4 s: turn the camera round to the card behind it while the card fades in
$S('#callcard').at(56.4).fadeIn(3);
$S('#PerspectiveCamera').at(56.4).animate({ to: { rotation: [0, 180, 0] } }, 3000);

The timeline now runs 59.4 seconds. This is the whole cut sheet:

10 Choose the camera and render it

  1. Open the Render tab and click + Add Shot under Camera Sequence. The first shot lands at 0 s on your scene camera, with a cut. Without a shot the render uses the Edit Camera, so the end-card turn would never be filmed — see Add a static hero camera to a render sequence for what a shot can do.
  2. Pick a resolution and frame rate. The scene camera is authored 16:9 and the card is landscape; a portrait crop is a manual resolution choice.
  3. Click Render & Export and wait — rendering runs in real time, so about a minute.
  4. The call card is re-fetched and re-baked fresh at render time at its true aspect — edit /about/callcard later and every future render picks up the change with no edits to this scene.
Everything above is git-versioned. Commit from the Git tab whenever you like — the timeline, the geometry, and the call-card reference (never a copy of its pixels) all round-trip through the same scene JSON. See the animation guide and the call-card guide for the full grammar this tutorial only samples.

11 Open the finished scene

pyth.json in tejaswigowda/test1 is the scene these blocks build: 50 tiles in 12 lines, the triangle, the three labels, the camera, the background and the call card, with the same 12 timeline tracks and the same 59.4-second clock. Open it, then scrub the Animations tab: at 24 s the 3×3 has unfolded, at 43 s all 25 tiles sit on the pad, and at 59.4 s the card fills the frame.

What was checked, and what differs. Every block on this page was pasted, one paste at a time, into an empty scene, with the three Text stencils, the Call card stencil and + Add Shot clicked where the text says so. The result was compared with pyth.json: the same 12 timeline tracks with the same events at the same times, and a frame at each of seven times from 0 to 52 s that differs from the published one by under 3% of its pixels. The end-card frame is the exception: the card is re-baked from the live /about/callcard page every time a scene loads, so two loads of the same scene can bake differently, and it was not compared. Three small differences are deliberate: the published file keeps its tiles at an offset inside their groups, so two of its positionX/positionY values read 9.4 and 4.4 where yours read 0.4 and −0.6 (the same place in the world); it nests the three labels in a Labels group, which nothing addresses; and its pad cells are numbered in a different order, with the same nine-and-sixteen split. Rendering (step 10) was not re-run for this revision.
