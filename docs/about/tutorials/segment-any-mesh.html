Cut any textured mesh into named parts

A model usually arrives as one mesh with one material, so nothing in the scene says "this is the beak". The editor's SEG tool cuts such a mesh into separate named, classed meshes in one undo step, from the evidence the file carries: which pieces of the texture are separate patches, and what colours are painted on them. This page uses it twice: on an avocado, where the file practically labels itself, and on a toy duck, where you have to read the evidence and decide. It also says where the method stops. Built with the JS Shell.

The tool is in the editor; this page uses it. SEG is a Shell global, with no setup. If you want to see what it does written out by hand, the older tutorial Cut an avocado into named parts, building the tool by hand builds the same thing step by step. The reference is guides/MESH_SEGMENT.md.

1 The idea, and how far it goes

A mesh has no idea what its triangles are, but two things in the file do carry hints. UV islands: an artist unwraps a model into patches of one texture image, and a patch that shares no vertices with any other is often a whole part (a seed, a beak, a wing). Painted colour: inside one patch, a ring of orange and a ring of cream are different things even though the triangles are all alike. SEG reports both, you decide what each piece is, and SEG.split cuts exactly there. It does not recognise anything: the names come from you (or from an AI that you show the report to), and it never loses a triangle.

The 3D advantage. The parts are only separable because the object is three-dimensional data: you can isolate the beak, see from behind that the cut is where you think it is, and tell the left wing from the right by where its centre sits in space. The report says that in one column.

It works when the model is one indexed mesh with UVs and a base-colour texture, and its parts are laid out as separate islands or are painted in clearly different colours. It does not work when the mesh has no UVs, or only vertex colours or one flat colour (there is no evidence to read); when a part shares an island and a colour with its neighbour (a boundary nobody painted cannot be found); or when the model has several materials, a skeleton or morph targets (SEG refuses these, and says why, rather than break them). And even when it works, it does not decide what an island is: the duck below has ten islands for about six parts, and you have to merge them.

Read it as evidence. Island 0 is the biggest, dark green: the skin. Island 1 is small and brown: the seed. Island 2 has a thickness of 0.000 (the third number of size), so it is flat, and it holds cream, dark green and lime: the cut face. Its 41 triangles are far too coarse to follow the rings painted on it, so the plan subdivides it and sorts the small triangles by colour. The at column is the island's centre across the whole mesh, 0 to 1 on x, y, z: the seed sits at the back of the mesh (z 0.12), the cut face just in front of it.

// Island 2 has thickness 0.000: it is flat, so it is the cut face, painted dark green (the rim), cream and lime (the flesh) and yellow-orange (the hollow).
// The flat face is far too coarse (41 triangles) to follow those rings, so it is subdivided four times (41 x 256) and each small triangle goes to the

5 Tidy up, and turn the gate on

The importer's wrapper (a node named after the file, an empty node and a camera the file carried) is all that is left of the original, and it is nameless and classless, which the labelling gate would refuse. Remove it, add a light to see by, and call requireLabels(true). (SEG.split removes the wrappers that hold only the mesh; this file's wrapper held a camera too.)

// The importer's wrapper (a node named after the file, an empty node and the camera the file carried) is all that is left of the original, and it is
// nameless and classless, so the gate would refuse the scene. Remove it, add a light to see by, and turn the gate on.
editor.execute(new RemoveObjectCommand(editor, scene.getObjectByName('Duck.glb')));
const sun = new THREE.DirectionalLight(0xfff1dd, 2.6); sun.name = 'KeyLight'; sun.position.set(80, 200, 160); sun.userData.customClasses = ['light'];
const sky = new THREE.HemisphereLight(0xdde6ff, 0x6a78c8, 1.4); sky.name = 'FillLight'; sky.userData.customClasses = ['light'];
editor.execute(new AddObjectCommand(editor, sun));
editor.execute(new AddObjectCommand(editor, sky));
requireLabels(true)      // from here on a commit is refused while any object is unnamed, duplicated or classless

6 Check the cut

A cut is only as good as the decision behind it, so look at it. SEG.preview gives every part its own flat colour, in one undoable step; isolate shows only one selector; SEG.restore() puts the textured material back.

SEG.preview('#Duck')                // every part its own flat colour
isolate('#Duck_Beak')               // only the beak
isolate('.eye')                     // only the two eyes (not their highlights)
isolate('.wing')
isolate('.left')                    // a wing, a tail piece, an eye and its highlight: everything on the left
showAll()
SEG.restore()                       // the textured materials, back

Orbit while previewing: a cut that looks right from the front can be wrong behind. Undo walks back through all of it, and a single undo of the split restores the importer's original, one mesh and its wrappers.

7 What it refuses

A plan that would lose or duplicate something is refused before anything changes, and the message says what to fix. These are the real messages, from this duck:

SEG.split('#LOD3spShape', { group: 'Duck', classes: ['toy'], parts: [{ island: 0, name: 'Duck_Body', classes: ['body'] }] })
//   SEG.split: every island must go to a part, and 9 of 10 have none
//   ... island: 0 twice          SEG.split: island 0 is used twice
//   ... name: 'Mesh'             SEG.split: every part needs a name an author chose, and "Mesh" is a default
//   ... classes: []              SEG.split: part "Duck_All" needs at least one class
//   ... no source in the plan    SEG.split: the plan needs a source: { url, licence, attribution }. A segmentation is a derivative work, and its record must say what it derives from and under what licence

It also refuses a node that is not a mesh, a skinned mesh (cutting would break the skeleton), a mesh with morph targets, and a colour cut on a mesh with no UVs or no base-colour texture. A mesh with several materials is not refused as a dead end: it is sent to SEG.byMaterial (step 9), which is better evidence than islands.

8 What the asset records

The cut is verifiable by anyone who has the file: the triangles are conserved and the parts do not overlap. The naming is only as good as what it was made from, so SEG.split writes that into the asset, on the Duck node's userData.segmentation (it travels in the scene file and in an exported .glb as extras):

FieldWhat it holds
source_url, source_licence, attributionWhere the original model is, under what licence, and the credit line. Required: the plan's source is refused without them, because a segmentation is a derivative work. SEG cannot check them; they are your statement
modificationsWhat was done to the model, written by SEG: the cut, any subdivision (138 to 2,208 triangles on each eye), that the material and texture are unchanged; plus anything the plan's modifications adds
planThe plan as given, verbatim: islands, subdivision, palette colours, names, classes
describeThe report the decision was made from: the islands with their sizes, centres and colours
parts, seg_versionTriangles per part, and the version of SEG that cut it
signalsFacts that may one day be worth refusing on, recorded and not acted on: the number of islands, the number of parts, the share of the surface the largest part covers (0.779 here), and compound names (Duck_Body_And_Head)

Every part also has its own descriptors, written when it is made, and its color is the colour of the texture under that part, with the main clusters and their shares, not of the whole atlas. The duck's beak is orange (#ff7e00), its eyes black (#000000), the highlights white (#ffffff) and its body yellow (#ffd800); the avocado's skin, pit, cavity and flesh are #47791c, #af6f2e, #f8d24d and #bfe36e. The material's own colour (one value for all parts, because they share it) is kept separately as materialColor. To see it, $S('#Duck_Beak').nodes[0].userData.descriptors.color.

The record is enough to do it again. Import the original model, and run the recorded plan:

const rec = $S('#Duck').nodes[0].userData.segmentation       // or the record from a scene or a .glb
editor.history.undo()                                          // (here, back to the single mesh)
SEG.replay('#LOD3spShape', rec)
//   replayed: all 10 parts match the record

SEG.replay first checks that the mesh is the one the record describes (the same islands, triangle counts, sizes and colours) and refuses, before changing anything, if it is not: for example the record has 10 islands and this mesh has 12; island 0 has 2280 triangles, the record says 2532. It then cuts, and refuses if any part has a different count from the record. This was run on the committed duck.json's record against a fresh import of Duck.glb, and all ten parts matched.

9 A mesh with several materials

Some formats (OBJ with a material library, for example) give one mesh several materials. That is the best case, not the worst: the author of the model assigned each triangle to a material, so there are no seam artefacts and no guessing. SEG.describe lists the materials; SEG.byMaterial cuts one part per material, named from the material's own name (or from the plan's parts: [ { material: 0, name, classes } ]). Every material must go to a part, and the mesh's groups must cover every triangle. The same record is written (with method: 'material'), the geometry is unchanged, and each part keeps its own material. A part can be cut further with SEG.split if it is textured. Checked on a six-material crate standing on a shelf: six parts, the group placed under the shelf in the same world position, undo restoring the crate, and a replay matching the record. (The glTF importer makes a separate mesh for every material, so glTF models arrive already cut this way.)

10 Use the parts

The point of the exercise is what you can now say. Anything that works on a selector works on a part: recolour, hide, animate, or let an AI edit "make the beak red" resolve to a mesh instead of a guess.

$S('#Duck_Beak').recolor('#e11')       // the beak
$S('.wing')                            // both wings
$S('.eye.left')                        // the left eye only
$S('.tail').scale(1.3)                 // both tail pieces

11 Your own model

  1. Import it, and find its mesh (list = []; scene.traverse(o => o.isMesh && list.push(o.name))).
  2. SEG.describe('#name'). If it says no uv or no texture, stop: there is nothing to read. If every island has the same colours and a similar size, expect to merge.
  3. Write the table, as in step 4: island, evidence, decision. Use size to tell flat from solid, at to tell left from right and front from back, and the colours to find painted regions.
  4. Write the plan, with its source; start with whole islands and SEG.preview. Only then add colour cuts, with the smallest subdivide that follows the paint (each step multiplies the triangles by 4).
  5. Check from behind and from above. Clean up the importer's wrapper, and requireLabels(true).
Save it. Commit from the Git tab. The scenes are duck.json and avocado.json in tejaswigowda/test1, with their textures beside them. The player at the top is pinned to a commit (@554a8ee), which never goes stale; these links read the branch head.
What was checked, and what differs. Every block on this page was pasted, in this order, into an empty scene after importing the .glb with the dialog's defaults, in the editor served from this repository. The duck scene was committed, loaded again from that commit, exported to a .glb and read back, to check that the descriptors and the record are in the file: one material shared by all ten parts, the group and its ten meshes with the triangle counts above (every object named and classed, the two lights, and the scene marked with requireLabels). The avocado scene was checked the same way: five parts, 483, 158, 2,286, 6,195 and 2,015 triangles. A single undo of each split restored the importer's original mesh, and redo brought the parts back. The refusal messages above were copied from the running editor. The recorded plan of the committed duck was replayed on a fresh import and matched all ten parts. The screenshots are frames of the duck scene with the editor's guide lines hidden. The parts' names are decisions made from the evidence; the colour boundaries (the avocado's rings, the eyes) follow the paint, not an anatomical or physical measurement. No video render was run for this page.
What a record cannot do. It cannot prove that the licence or attribution you give is right (SEG only refuses to run without them); it cannot say that the names are correct, only what they were made from; and a replay depends on the texture decoding to the same pixels, which it does on the same browser (a different one may move a colour by a count or two, which the check allows for). Records made before SEG 1.1.0 (the first release) kept only the source name and the part sizes.
